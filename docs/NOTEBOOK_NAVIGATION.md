# Notebook navigation repair

A public user walk found that a comparison deep link opened light, but related-lesson and list buttons changed only React state. The URL remained `lesson=light`; refresh reopened light and Back skipped the related lesson.

Lesson and list transitions now push native same-origin history entries, preserving custom history fields and unrelated query/fragment context. Next's patched history adapter copies its own internal state; internal bypass flags are deliberately not passed back to it. Next App Router supports native history integration: https://nextjs.org/docs/app/building-your-application/routing/linking-and-navigating#using-the-native-history-api . A `popstate` listener reads the destination, restores committed stage/settings, and does not write journal answers. Same-lesson anchor history leaves active editing, stage, and settings intact. Invalid lesson IDs resolve to the catalogue and are removed with replacement, without an extra history entry. The actual URL, rather than an old server prop, is the source on reload/owner hydration. Navigation to another route is never rewritten by the notebook listener.

Internal buttons retain the existing explicit unsaved-edit confirmation and cleanup-failure refusal. Back/Forward is not intercepted or trapped: an active explicit edit becomes pending owner-scoped recovery. The committed record is unchanged. If tab storage fails, a recovery copy remains in this mounted component and a warning asks the person to restore/save or copy before refresh. This does not promise recovery after reload with unavailable storage, tab closure, or cross-route unmount. Existing same-base/deletion checks still control recovery. Global route changes retain the existing tab-draft protection, not a guaranteed confirmation dialog.

Focus uses `preventScroll` followed by an instant `scrollIntoView` to avoid relying on the browser's minimal default focus scroll, which left headings partly under the fixed desktop navbar. Scoped heading margins use 1.5rem with the in-flow mobile navigation and 8rem with the fixed desktop navigation. No animation, timeout, or history interception is added. Basis: https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html . This is not a claim of full WCAG compliance or a browser-verified narrow-layout result.

Synthetic regressions cover related/list URL updates, reload, Back/Forward, history state preservation, invalid targets, unchanged original records, declined internal draft exits, Back recovery (including tab-write failure), and explicit heading focus/scroll calls. Existing owner isolation and stale/deleted draft tests remain applicable. The synthetic history adapter mirrors the pinned Next 15.5.29 bypass/copy behavior; it is not a full browser framework integration test. Actual desktop/narrow-browser verification is a separate release check.

Verification: 293 tests / 46 files passed; TypeScript passed; production build with CAS and cloud-sync flags enabled passed; all 10 local HTTP smoke routes passed. Independent source review passed. No real account/record actions or publication were performed.
