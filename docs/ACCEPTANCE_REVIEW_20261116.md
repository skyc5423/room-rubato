## Correcting historical verification gaps

- Current CI uses isolated Playwright browser contexts and synthetic records. The old user-browser incognito restriction no longer blocks these **synthetic** journeys; it still does not prove real two-account/two-device isolation.
- Chromium accessibility/reflow checks use **390 and 320 CSS-pixel** widths. The 320px suite completes all 12 questionnaires/results and checks overflow; it also covers sources, literature comparison and blocked artwork. There is no exact 375px fixture in the current script. Earlier statements that no narrow viewport could be exercised are historical, not current candidate limits.
- Notebook lifecycle checks run in Chromium, Firefox and WebKit. The three-engine notebook suite is not a claim that every screen was tested in each engine or at phone sizes. Linux WebKit is not physical Safari.
- Virtual audio output and AudioContext lifecycle checks exercise manual start/stop, background/pagehide cancellation and explicit replay. They do not verify perceived loudness, sound quality or audible playback on the user's device.
- Backup docs record later bucket/writer/limited-role preparation after the canceled login checkpoint. Those are historical provisioning records, not a fresh live configuration audit or successful backup. No new login is requested here.

## Actual gap closed in this review: daily keyboard orientation

Both home and `/daily` removed the activated choice button when revealing the hypothetical situation or result without moving focus. Two new component regressions failed before the fix. The follow-up focuses the new situation/result heading only after an explicit answer, using a negative tab index. Initial saved-record loading, reload, account change and calendar/question changes do not request focus. Intent is owner/day/question/phase-bound; immediate persisted-state updates retain result focus. Answer contents, scores and storage formats are unchanged.

Primary guidance read for this review: [W3C WAI multi-page forms](https://www.w3.org/WAI/tutorials/forms/multi-page/) recommends clear stage orientation and headings. Applying that principle to these same-page transitions is an implementation judgment, not a full WCAG conformance claim. New browser assertions use keyboard activation on both entry points and check reload does not steal focus.
